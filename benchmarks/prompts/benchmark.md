# Оптимизированный запрос на аудит эффективности

Проведи воспроизводимое сравнение трёх групп одного и того же AI coding agent на
трёх задачах: сайт, браузерная игра и прототип веб-приложения. Группы:

- **без скилов** — только общий промпт;
- **lite** — без скилов, плюс замороженный текст конвенций из `prompts/lite.md`;
- **workflow** — явный вызов session-start, plan-and-orchestrate,
  session-handover и session-end с их штатными скриптами.

Выполни реальные прогоны, а не прогноз эффективности.

До запуска зафиксируй требования, исходные файлы, скрытые проверки, критерии и
seed порядка. Для каждой задачи и группы создай отдельную копию; минимум три
повтора на ячейку в сбалансированном порядке. Используй одну модель, одинаковый
reasoning effort, инструменты и лимит времени. Отключи посторонние скилы,
плагины и память. Самостоятельные тесты и заметки разрешены во всех группах.

В каждом проекте сначала реализуй первую версию, затем передай изменение
требования новой сессии без истории чата. Она продолжает по файлам проекта.
Не передавай исполнителю результаты скрытой проверки и не исправляй его решение
после оценки. Не меняй плагин, конвенции или критерии по ходу эксперимента.

Измерь фактическое время обеих сессий, input/cached input/output токены,
выполнение проверяемых требований, воспроизводимые уникальные дефекты и качество
передачи. Учитывай чтение скилов и ведение состояния в затратах. Не складывай
cached input второй раз. Отдели ошибки стенда и неуспешные команды от багов
продукта. Не оценивай реальные токены по длине текста.

Сохрани промпты, конфигурацию изоляции, хэши, сырые журналы, снимки проектов и
результаты тестов. Покажи медианы и разброс по повторам, разницу каждой группы
с группой без скилов и отдельно workflow против lite: это решающий вопрос,
окупает ли runtime свою стоимость поверх одних конвенций. Сообщи результат даже
при отсутствии выигрыша и не переноси его на других провайдеров, устройства и
параллельные сессии. Укажи следующий эксперимент, необходимый для этих выводов.
